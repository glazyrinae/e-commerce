## 📋 Основные правила

### 🛑 ПРАВИЛО №0: Всегда проверяйте pyproject.toml

ПЕРЕД внесением ЛЮБЫХ изменений или нажатием Ctrl+S:

1. Откройте pyproject.toml и проверьте:
   - Требуемую версию Python (project.requires-python)
   - Список зависимостей и их точные версии (project.dependencies)
   - Dev-зависимости (project.optional-dependencies.dev)
   - Конфигурации линтеров/форматтеров/тайп-чекеров (black, ruff, mypy, pytest, djlint и т.д.)
   - Скрипты и entry points

2. Строго соблюдайте ограничения:
   - Не используйте синтаксис Python, не поддерживаемый указанной версией
   - Не импортируйте пакеты, которых нет в pyproject.toml
   - Следуйте настроенным правилам форматирования и линтинга (длина строки, кавычки, сортировка импортов)

3. После изменений:
   - Если добавили новую зависимость → сразу обновите pyproject.toml
   - Если изменили модели → проверьте, нужны ли миграции
   - Если затронули конфигурацию → убедитесь, что не сломали инструменты из pyproject.toml

## 📝 Стандарты кода

### 🐍 Python
- Следуйте PEP 8
- Обязательные type hints (синтаксис Python 3.9+)
- Максимальная длина строки: берётся из pyproject.toml
- Строки в двойных кавычках ""
- Docstring: стиль Google или NumPy (согласно конфигурации линтера)

### 🎛 Django-специфика

#### Модели (models.py)
- Используйте verbose_name и verbose_name_plural
- Добавляйте ordering и indexes в Meta
- Реализуйте __str__ с возвращаемым типом str
- Для внешних ключей используйте on_delete=models.CASCADE (или другой явный вариант)

Пример:
```
from django.db import models

class Product(models.Model):
    name = models.CharField("Название", max_length=255)
    slug = models.SlugField(unique=True)
    created_at = models.DateTimeField(auto_now_add=True)

    class Meta:
        verbose_name_plural = "Товары"
        ordering = ["-created_at"]
        indexes = [models.Index(fields=["slug"])]

    def __str__(self) -> str:
        return self.name
```

#### Представления (views.py)
- Используйте FBV с декораторами или CBV
- Всегда типизируйте request и response
- Валидируйте входные данные на входе
- Ловите конкретные исключения, а не голый except Exception

Пример:
```
from django.http import JsonResponse, HttpRequest
from django.views.decorators.http import require_POST

@require_POST
def api_search(request: HttpRequest) -> JsonResponse:
    """Обработка AJAX-поиска товаров."""
    try:
        # логика
        return JsonResponse({"success": True})
    except ValueError as e:
        return JsonResponse({"success": False, "message": str(e)}, status=400)
```

#### Сервисный слой (services.py)
- Бизнес-логика только здесь, не во views
- Используйте внедрение зависимостей (DI)
- Выбрасывайте кастомные исключения, а не ValueError

## 🚫 Чего избегать

| Ошибка | Почему это плохо | Как правильно |
|--------|------------------|---------------|
| Игнорировать pyproject.toml | Сломает CI, упадёт типизация, появятся зависимости-призраки | Всегда сверяйтесь с конфигом перед сохранением |
| Пихать бизнес-логику во views | Views становятся нечитаемыми, невозможно тестировать | Выносите в services.py или utils/ |
| Model.objects.get() без обработки | DoesNotExist → 500 ошибка | Используйте .filter().first() или try/except DoesNotExist |
| Забывать select_related / prefetch_related | N+1 запросов, тормоза на проде | Добавляйте оптимизацию сразу при работе с FK/M2M |
| Хардкодить секреты/пути | Уязвимости, непереносимость | Используйте os.environ или django.conf.settings |
